# ML system design — правила для llm-service и данных PF2e

Эти правила действуют, когда работа идёт над RAG/LLM-сервисом или загрузкой данных
правил. Основной свод — в корневом `CLAUDE.md`; здесь только доменные детали.

## Разделение offline / online
- Ingestion (загрузка, чанкинг, индексация книг) — отдельный процесс от online-пути
  (retrieval + генерация ответа). Не смешивать в одном модуле/функции.
- Online-путь не должен переиндексировать или скачивать данные на лету.

## Всё через конфиг, ничего «магического»
- Имена моделей, `k`, температура, размеры чанков, пути, имена коллекций —
  только из `app/core/config.py` / env. Никаких констант в коде бизнес-логики.
- Провайдер LLM берётся через `app/core/llm_provider.py`. Переключение
  Ollama ↔ облако — конфигом, без правок узлов графа.

## Промпты и параметры — версионируемые артефакты
- Все промпты собраны в `agents_core/prompts.py`, а не разбросаны строками.
- Изменение промпта или параметров ретривала = осознанное изменение с прогоном evals.

## Воспроизводимость ingestion
- Фиксируем источник данных и его версию; логируем, что и когда проиндексировано.
- Индексация детерминирована: один и тот же вход → один и тот же индекс.

## Оценка перед доверием (evals)
- Перед изменением сценария/промптов прогоняем небольшой golden-набор Q&A.
- Изменение, ухудшающее качество ответов, не мёржим.
- Eval-набор живёт в репозитории и растёт вместе с найденными ошибками.

## Наблюдаемость
- Структурно логируем: запрос, выбранные источники (id/раздел), `k`, задержку.
- По логам должно быть видно, почему модель ответила именно так.

## Честность и границы ответа
- Нет релевантного контекста — прямо об этом говорим, правила не выдумываем.
- Ответы по правилам сопровождаем ссылкой на источник (раздел/страница книги).

## Данные и лицензии
- PII пользователя в LLM не отправляем.
- Индексируем и храним только открытый контент (PF2e ORC / SRD).
  Закрытый текст книг — не скачиваем, не храним, не индексируем.
